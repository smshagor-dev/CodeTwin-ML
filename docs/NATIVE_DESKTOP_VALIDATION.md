native IPC and application SQLite persistence. WebKitWebDriver controlled the

## Defect found and fixed

Modal's focus effect depended on the caller's `onClose` callback. Controlled form
updates replace that callback, so each character reran focus initialization and
focused Close. Native URL entry produced only `h`; a space in JSON activated
Close and dismissed the composer.

Focus setup/cleanup now depends only on open state. A ref receives the latest
close callback, preserving current busy/authorization behavior. The browser
regression types character-by-character, asserts full input value and focus,
then verifies Escape closure and trigger focus restoration. The corrected native
binary completed the policy/report flow.

Also passed: 37 frontend tests, TypeScript/production build and production route
smoke including the keyboard regression, 8 lazy routes, mobile layout and zero
page errors. Browser regression uses fixture IPC and remains separate from this
native evidence.

## Repeating the checks

On Linux with GTK3/WebKitGTK development libraries:

```sh
npm ci --ignore-scripts
npm run build
cargo build -p codetwin-desktop --features tauri/custom-protocol
./target/debug/codetwin-desktop
```

Use a fresh application data directory. Save settings, import the fixture through
the OS picker, inspect source evidence, run static analysis/QA discovery and
restart. For policy testing, use only an owned fixture with explicit
authorization, distinct identities and exact expected object. Export both
reports via OS dialogs; inspect credential redaction, repeat resets and restart
persistence. Run the automated keyboard/route regression separately:

```sh
npx playwright install chromium
node scripts/security/verify-desktop-routes.cjs
```

## Remaining gates

This is native Linux GUI validation on a virtual display, not physical hardware
or Windows validation. It does not exercise every advanced command, packaged
installation, signing, Windows strict QA execution, repair apply/rollback, GPU
behavior or exhaustive accessibility. Windows signed installer/install/launch/
uninstall checks remain required under existing release gates. No release or
version change occurred.
